# 최종 Train–Trackman 선수 ID 매핑 검증 보고서

기준일: 2026-08-20  
대상: 최종 `trackman_id`가 연결된 Train 1,275,274행  
목적: Train 선수 ID와 Trackman 선수 ID의 안전한 대응 범위를 계산하고, 선수 정보로 기존 투구 매칭을 추가 검증

## 1. 결론

선수 ID는 대부분 매핑할 수 있지만 팀처럼 전체를 하나의 일대일 대응표로 바로 확정할 수는 없다.

- exact 경기 기반 양방향 안전 전역 매핑: **투수 695명 + 타자 693명 = 1,388개 역할별 선수 매핑**
- `시즌+게임타입+팀+역할+선수` 기준 양방향 안전 키: **5,109개**
- 안전 매핑과 일치한 투수·타자 역할 관측: **2,517,572건, 98.71%**
- 안전 매핑과 불일치: **618건**
- exact 기준 충돌 또는 기준 부족: **32,358건**
- 선수 불일치가 있는 Train 행: **613행**
- 선수 불일치가 있는 Train 경기: **237경기**

선수 정보는 안전한 부분부터 ID 대응표로 사용할 수 있고, 기존 투구 매칭을 추가 검증하는 데도 유용하다. 그러나 불일치 618건을 곧바로 투구 오매칭으로 판정하면 안 된다. exact 경기 자체에서도 같은 Train 선수 ID가 여러 Trackman 선수 ID로 나뉘는 사례가 있어 선수 ID 원본의 별칭·오류 가능성이 함께 존재하기 때문이다.

## 2. 입력과 선수 범위

### 입력

- Train 투구 기록과 Trackman 투구 기록을 기준으로 검증했다.

### 사용 컬럼

Train:

```text
row_id
game_block_id
season
game_type
pitcher_id
batter_id
pitcher_team_id
batter_team_id
trackman_id
trackman_match_basis
```

Trackman:

```text
trackman_id
season
pitcher_trackman_id
batter_trackman_id
pitcher_team
batter_team
```

최종 ID 연결 행에는 위 선수·팀 컬럼의 결측이 0건이었다.

| 선수 범위 | Train 고유 선수 ID |
|---|---:|
| 최종 연결 행의 투수 | 777 |
| 최종 연결 행의 타자 | 806 |
| exact 경기에서 관찰된 투수 | 702 |
| exact 경기에서 관찰된 타자 | 735 |

투수와 타자는 역할을 분리해 분석했다. 같은 숫자 ID가 두 역할에 나타나더라도 하나의 매핑으로 합치지 않았다.

## 3. 매핑 키와 안전 조건

### 3.1 엄격한 시즌·팀 매핑

정방향:

```text
(role, season, game_type, Train team_id, Train player_id)
→ (Trackman team_name, Trackman player_id)
```

역방향:

```text
(role, season, game_type, Trackman team_name, Trackman player_id)
→ Train player_id
```

정방향 후보가 하나뿐이고 그 Trackman ID의 역방향 Train 선수도 하나뿐일 때만 양방향 안전 매핑으로 인정했다.

### 3.2 전역 선수 매핑

선수가 시즌·게임타입·팀 조합을 옮겼을 때도 확인할 수 있도록 역할별 전역 매핑을 별도로 만들었다.

```text
(role, Train player_id) → Trackman player_id
```

이 경우에도 정방향과 역방향이 모두 하나일 때만 안전 매핑으로 인정했다.

### 3.3 검증 순서

1. exact 경기의 엄격한 양방향 매핑 적용
2. 해당 시즌·팀 exact 키가 없으면 exact 전역 양방향 매핑 적용
3. 두 기준 모두 없거나 충돌하면 `기준 부족·충돌`로 분리
4. 안전 기준과 다른 Trackman 선수 ID가 연결되면 `선수 불일치`로 분리

## 7. 충돌이 생길 수 있는 이유

선수 충돌은 다음 원인이 섞일 수 있다.

1. 같은 실제 선수가 Trackman에서 복수 선수 ID로 등록됨
2. Train 또는 Trackman 선수 ID 원본 오류
3. 한 경기 안에서 선수 ID가 잘못 바뀐 기록
4. 자동·구간 투구 매칭이 같은 팀의 다른 선수를 선택한 경우
5. 선수 이적, 1군·퓨처스 이동 또는 시즌별 등록 정보 차이

exact 경기 자체의 23개 충돌은 투구 정렬이 아니라 선수 ID 메타데이터에도 불완전성이 있음을 보여준다. 따라서 자동·구간 매칭에서 발견된 618개 선수 불일치를 모두 투구 오매칭으로 해석할 수 없다.

## 8. 권장 선수 매핑 등급

선수 ID 대응표를 만들 때 다음 등급을 권장한다.

### 확정 매핑

- exact 경기에서 관찰됨
- 시즌·게임타입·팀·역할 정방향 후보가 하나
- 같은 Trackman 선수 ID의 역방향 Train 선수도 하나

### 전역 보조 매핑

- 해당 시즌·팀 exact 키는 없음
- 다른 시즌·팀을 포함한 역할별 전역 exact 대응이 양방향 일대일
- 현재 행의 팀 매핑도 일치

### 강한 잠정 후보

- 복수 ID 중 하나가 여러 exact 경기에서 압도적
- 손잡이, 팀 이동, 경기별 등장 흐름이 일관됨
- 소수 후보 ID가 단일 경기 또는 짧은 구간에만 등장

### 보류

- 후보 비율이 비슷함
- 정방향 또는 역방향이 다대일
- exact 기준 자체가 없음
- 안전 기준과 현재 연결 선수 ID가 다름

최종 Train에 선수 매핑 컬럼을 추가한다면 `confirmed`, `global_exact`, `provisional`, `conflict`, `unanchored`를 구분하고, 잠정 후보를 확정 ID 컬럼에 섞지 않는 것이 안전하다.

## 9. 기존 선수 매핑 문서와의 차이

기존 2026-08-16 선수 매핑 보고서는 당시 확정된 2,700경기와 Trackman ID 810,723개를 기준으로 만들었다.

이 문서는 현재 최종 결과를 기준으로 다시 계산했다.

- 최종 Trackman ID 연결 행: 1,275,274행
- exact 경기 행: 773,446행
- 전체 자동·구간 매칭까지 검증 대상에 포함
- 정방향 유일성뿐 아니라 역방향 일대일성도 안전 조건에 포함
- 선수 불일치 행과 경기 범위를 별도로 집계

따라서 현재 최종 투구 매칭의 선수 ID 검증에는 이 문서를 기준으로 사용한다. 기존 문서는 이전 분석 단계의 이력 자료다.

## 10. 최종 판정

선수 ID 매핑은 안전한 부분부터 자동화할 수 있다. exact 기준으로 양방향 일대일인 전역 역할별 선수 1,388개와 엄격 키 5,109개는 확정 대응표의 기반으로 사용할 수 있다.

다만 역할 관측 618건은 안전 대응표와 다르고, 32,358건은 exact 기준이 부족하거나 자체 충돌이 있다. 이 두 그룹은 선수 ID를 이용해 최종 투구 매칭을 추가 검토할 대상이며, 현재 단계에서 선수 정보만으로 Trackman ID를 자동 변경하거나 삭제해서는 안 된다.

## 11. 현재 기준 선수 ID 대응표

### 11.0 간단 조회용 대응표

직접 조회할 때는 간단 선수 ID 대응표를 사용한다. 컬럼은 `role`, `season`, `game_type`, `train_team_id`, `train_player_id`, `current_trackman_player_id`, `mapping_status`만 포함한다. `role`은 같은 선수 ID가 투수·타자 역할별로 다르게 해석될 수 있어 유지하며, 상세 대응표에는 기존의 근거·충돌 정보가 계속 보존된다.

전역 기준으로만 조회할 때는 간단 선수 전역 대응표를 사용한다. 컬럼은 `role`, `train_player_id`, `current_trackman_player_id`, `mapping_status`이다.

### 11.1 엄격 키 대응표

현재 선수 ID 엄격 대응표는 Train의 전체 `역할 + 시즌 + 게임타입 + 팀 ID + 선수 ID` 6,566개 조합을 포함한다.

| 분류 | 키 수 | 확정 ID 처리 |
|---|---:|---|
| exact 엄격 양방향 확정 | 5,109 | `current_trackman_player_id`에 기록 |
| 전역 exact 양방향 보조 매핑 | 1,143 | 엄격 키가 없을 때만 기록 |
| 충돌·exact 근거 부족 | 314 | 확정 ID 공란, 후보와 원인을 별도 컬럼에 기록 |

확정 ID가 있는 엄격·전역 보조 매핑은 총 6,252개 조합이다. 충돌 또는 근거 부족 조합에서는 최빈 후보를 `current_trackman_player_id`에 넣지 않는다.

### 11.2 역할별 전역 대응표

현재 선수 ID 전역 대응표는 전체 `역할 + Train 선수 ID` 1,622개를 정리한다.

| 상태 | 선수 역할 키 수 |
|---|---:|
| 양방향 exact 확정 | 1,388 |
| 복수 Trackman ID 충돌 | 25 |
| 역방향 복수 Train 선수 충돌 | 24 |
| exact 근거 없음 | 185 |

실제 행에 적용할 때는 엄격 대응표를 먼저 사용하고, 해당 엄격 키 자체가 exact에 없을 때만 전역 대응표를 보조로 사용한다.

세 표를 함께 보려면 통합 대응표 엑셀의 `Player_Strict`, `Player_Global` 시트를 사용한다.
